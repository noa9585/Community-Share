# תרשימי זרימה

## המסלול המרכזי

```mermaid
flowchart TD
    A[הרשמה באימייל וסיסמה] --> B[אימות כתובת האימייל]
    B --> C[מסך המתנה לאישור]
    C --> D{אדמין מאשר?}
    D -- כן --> E[מייל ברוך הבא + כניסה לאתר]
    D -- חוסם --> X[מסך חשבון חסום]
    E --> F[חיפוש וסינון בקטלוג]
    F --> G[עמוד פריט + לוח תפוסות]
    G --> H[בחירת תאריכים וכמות]
    H --> I{הכמות פנויה?}
    I -- לא --> H
    I -- כן --> J[שליחת בקשה + מייל לבעל הפריט]
    J --> K{בעל הפריט}
    K -- דוחה --> L[מייל דחייה לשואל]
    K -- מאשר --> M[נוצרת השאלה, המלאי יורד, התאריכים נחסמים + מייל אישור]
    M --> N[מסירת הפריט וסימון קבלת פיקדון]
    N --> O[תזכורת יום לפני מועד ההחזרה]
    O --> P[השואל מסמן החזרתי + מייל לבעלים]
    P --> Q[בעל הפריט מאשר החזרה]
    Q --> R[ההשאלה נסגרת והמלאי חוזר]
```

## מכונת המצבים של בקשה והשאלה

```mermaid
stateDiagram-v2
    [*] --> pending: שליחת בקשה
    pending --> cancelled: המבקש מבטל
    pending --> rejected: בעל הפריט דוחה
    pending --> approved: בעל הפריט מאשר
    cancelled --> [*]
    rejected --> [*]

    state "השאלה (loans)" as loan {
        [*] --> active
        active --> late: מועד ההחזרה עבר (משימה יומית)
        active --> returned_pending_confirmation: השואל מסמן שהחזיר
        late --> returned_pending_confirmation: השואל מסמן שהחזיר
        active --> completed: הבעלים מאשר שהפריט חזר
        late --> completed: הבעלים מאשר שהפריט חזר
        returned_pending_confirmation --> completed: הבעלים מאשר החזרה
        completed --> [*]
    }

    approved --> loan: נוצרת השאלה באותה טרנזקציה
```

בעל הפריט יכול לסגור השאלה גם אם השואל לא סימן "החזרתי" – הוא זה שיודע אם הפריט אכן חזר.

## מחזור החיים של פריט

```mermaid
stateDiagram-v2
    [*] --> pending: בעלים מוסיף פריט
    pending --> approved: אדמין מאשר (מייל לבעלים)
    pending --> rejected: אדמין דוחה
    approved --> pending: שינוי שם, תיאור, קטגוריה או תמונה
    rejected --> pending: הבעלים עורך ושולח שוב
    approved --> [*]: מחיקה (רק כשאין השאלה פתוחה)
```

## מה קורה בפעולה אחת (דוגמה: שליחת בקשה)

```mermaid
sequenceDiagram
    participant B as דפדפן
    participant S as שרת (Server Action)
    participant D as מסד הנתונים
    participant R as Resend

    B->>S: טופס בקשה (פריט, תאריכים, כמות)
    S->>S: בדיקת משתמש מאושר + ולידציה + הגבלת קצב
    S->>D: create_borrow_request()
    D->>D: בדיקת תאריכים, בעלות וזמינות
    D-->>S: מזהה הבקשה
    S->>D: קריאת פרטי בעל הפריט (צד שרת בלבד)
    S->>R: שליחת מייל
    R-->>S: הצלחה או כישלון
    S->>D: רישום ב-email_log
    S-->>B: "הבקשה נשלחה"
```
