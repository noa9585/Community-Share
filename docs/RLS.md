# הרשאות – Row Level Security

## העיקרון: קריאה מסוננת, כתיבה רק דרך פונקציות

RLS מופעל על **כל** הטבלאות. ההרשאות בנויות כך:

1. **אורח לא מחובר (`anon`)** – אין לו שום הרשאה, לא לטבלאות ולא לפונקציות.
2. **משתמש מחובר (`authenticated`)** – יש לו הרשאת `SELECT` בלבד, ומדיניות ה-RLS קובעת אילו שורות יחזרו.
3. **אין מדיניות `INSERT` / `UPDATE` / `DELETE` כלל.** כל כתיבה נעשית דרך פונקציית מסד
   (`SECURITY DEFINER`) שלוקחת את זהות הקורא מ-`auth.uid()` – אף פעם לא מפרמטר – ובודקת בעצמה סטטוס,
   בעלות וחוקים עסקיים.

למה כך ולא מדיניות כתיבה רגילה? מדיניות `UPDATE` מתירה לשנות *כל עמודה* בשורה. בעל פריט שמורשה לעדכן
את הפריט שלו היה יכול גם לאשר אותו לעצמו; שואל שמורשה לעדכן את ההשאלה שלו היה יכול לסמן אותה כ"הושלמה".
פונקציה מגדירה במדויק איזה שינוי מותר.

## מי רואה מה (SELECT)

| טבלה | מי רשאי לקרוא |
|---|---|
| `users` | כל אחד את השורה שלו; אדמין את כולם |
| `public_profiles` (view) | חברים מאושרים רואים **שם ואזור בלבד** של חברים מאושרים אחרים – בלי אימייל |
| `categories` | חברים מאושרים |
| `areas` | כולם, גם לפני התחברות (טופס ההרשמה צריך את הרשימה). אין בה מידע אישי |
| `items` | חבר מאושר רואה: פריטים מאושרים, הפריטים שלו בכל סטטוס, ופריטים שיש לו בקשה עליהם. אדמין רואה הכול |
| `item_images` | מי שרשאי לראות את הפריט |
| `borrow_requests` | המבקש, בעל הפריט ואדמין בלבד |
| `loans` | מי שרשאי לראות את הבקשה |
| `conversations`, `messages` | **שני המשתתפים בשיחה בלבד.** גם אדמין אינו רואה שיחות פרטיות |
| `notifications` | כל אחד את ההתראות שלו בלבד |
| `reports` | מי שדיווח ואדמין. מי שדווח עליו אינו רואה את הדיווח |
| `email_log`, `admin_audit_log` | אדמין בלבד |
| `rate_limits` | אף אחד (רק השרת, עם service role) |

משתמש במצב `pending` או `blocked` רואה רק את שורת הפרופיל של עצמו. החסימה מיידית: המדיניות בודקת את
הסטטוס בכל שאילתה, כך שגם סשן שעדיין בתוקף מפסיק לקבל נתונים.

## מי רשאי לשנות (דרך פונקציות)

| פעולה | פונקציה | מי רשאי |
|---|---|---|
| עדכון שם ואזור בפרופיל | `update_my_profile` | המשתמש עצמו. **אין** פונקציה שמשנה `role`, `status` או `email` למשתמש עצמו |
| יצירת פריט | `create_item` | חבר מאושר; הפריט נוצר תמיד כ-`pending` |
| עריכה / מחיקה של פריט | `update_item`, `delete_item` | בעל הפריט בלבד; אי אפשר למחוק פריט שמושאל |
| הוספה / הסרה של תמונה | `add_item_image`, `remove_item_image` | בעל הפריט בלבד, ורק בתיקייה שלו |
| שליחת בקשת השאלה | `create_borrow_request` | חבר מאושר, לא על פריט שלו |
| ביטול בקשה | `cancel_borrow_request` | המבקש, כל עוד הבקשה ממתינה |
| אישור / דחיית בקשה | `approve_borrow_request`, `reject_borrow_request` | בעל הפריט בלבד |
| "החזרתי" | `mark_loan_returned` | השואל בלבד |
| אישור החזרה | `confirm_loan_return` | בעל הפריט בלבד |
| סימון קבלת פיקדון | `mark_deposit_received` | בעל הפריט בלבד |
| אישור / חסימה / שחרור משתמש | `admin_set_user_status` | אדמין; לא על עצמו ולא על אדמין אחר |
| אישור / דחיית פריט | `admin_set_item_approval` | אדמין |
| פתיחת שיחה על פריט | `start_conversation` | חבר מאושר מול בעל הפריט. בעל פריט יכול לפתוח שיחה רק עם מי שכבר ביקש את הפריט |
| שליחת הודעה / תמונה | `send_message` | אחד משני המשתתפים בשיחה; תמונה רק מהתיקייה של השולח |
| סימון שיחה או התראות כנקראו | `mark_conversation_read`, `mark_notifications_read` | המשתמש, על שלו בלבד |
| דיווח על פריט או משתמש | `create_report` | חבר מאושר; לא על עצמו ולא על פריט שלו; עד 10 דיווחים פתוחים |
| עדכון סטטוס דיווח | `admin_update_report` | אדמין; נרשם ביומן |
| סגירת השאלה במקום הבעלים | `admin_close_loan` | אדמין; נרשם ביומן, ושני הצדדים מקבלים התראה |
| סטטיסטיקות | `admin_stats` | אדמין |
| ניהול קטגוריות ואזורים | `admin_save_category`, `admin_delete_category`, `admin_save_area`, `admin_delete_area` | אדמין; נרשם ביומן |
| סימון איחורים ותזכורות יומיות | `cron_mark_late_loans`, `cron_create_return_reminders` | השרת בלבד (service role) |

התראות והודעות מערכת בצ'אט אינן נכתבות על ידי אף משתמש: triggers במסד יוצרים אותן כשבקשה, השאלה, פריט
או משתמש משנים סטטוס. לכן אי אפשר לזייף התראה או לדלג עליה.

כל הפונקציות מוגדרות עם `search_path` ריק, והרשאת ההרצה שלהן נשללה מ-`PUBLIC` ומ-`anon` וניתנה
במפורש רק למי שצריך.

## פרטי קשר

כתובות אימייל של חברים אחרים אינן ניתנות לקריאה מהטבלה. הפונקציה `get_request_contacts` מחזירה את
הכתובת של הצד השני רק למי שמעורב בבקשה: בעל הפריט רואה את כתובת המבקש, והמבקש רואה את כתובת הבעלים רק
אחרי שהבקשה אושרה.

## Storage – תמונות הפריטים

ה-bucket `item-images` **פרטי**, מוגבל ל-1MB לקובץ ולסוגי JPEG, PNG ו-WebP.

| פעולה | מי רשאי |
|---|---|
| קריאה | חברים מאושרים בלבד, דרך קישור חתום שתקף לשעה |
| העלאה | חבר מאושר, רק לנתיב `<המזהה שלו>/<פריט שבבעלותו>/...` |
| מחיקה | חבר מאושר, רק בתיקייה שלו |

ה-bucket `chat-images` (תמונות מהצ'אט) פרטי גם הוא. הנתיב הוא `<שיחה>/<שולח>/...`: רק שני המשתתפים
בשיחה יכולים לקרוא, וכל אחד כותב רק לתיקייה שלו.

## Realtime

הטבלאות `messages`, `notifications`, `borrow_requests` ו-`loans` משודרות ב-Supabase Realtime. Realtime
מחיל את אותה מדיניות `SELECT`: מנוי מקבל אירוע רק על שורה שהוא רשאי לקרוא. הדפדפן רק מאזין, והאירוע
משמש כאות לרענן את הדף דרך השרת.

## איך זה נבדק

נכתבה בדיקה אוטומטית שמריצה 73 תרחישים מול מסד הנתונים האמיתי, בתוך טרנזקציה שמתבטלת בסופה. משתמשים
מדומים מנסים בה, בין השאר: להפוך את עצמם לאדמין, לאשר לעצמם בקשה, לאשר לעצמם פריט, לערוך פריט של אחר,
לקרוא אימייל של חבר אחר, ולגשת בלי התחברות. כל הניסיונות נדחו.

בדיקה נפרדת מול ה-API של Storage אישרה שהעלאה לתיקייה של משתמש אחר נדחית, שקובץ שאינו תמונה נדחה,
ושקישור לא חתום לתמונה אינו נפתח.
