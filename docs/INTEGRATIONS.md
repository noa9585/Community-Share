# חיבורים חיצוניים

## Resend – מיילים אוטומטיים

### למה זה מוסיף ערך

השאלת ציוד תלויה בכך שאנשים יגיבו בזמן: בעל פריט צריך לדעת שמחכה לו בקשה, והשואל צריך לזכור להחזיר.
בלי הודעות, כל אחד היה צריך להיכנס לאתר ולבדוק. המיילים הופכים את המערכת מלוח מודעות למשהו שמניע את
התהליך קדימה.

### אילו מיילים נשלחים

| # | אירוע | נמען | תוכן | כפתור |
|---|---|---|---|---|
| 1 | נשלחה בקשת השאלה | בעל הפריט | מי מבקש, איזה פריט, כמות ותאריכים | לצפייה בבקשה |
| 2 | בקשה אושרה | השואל | הפריט והתאריכים; היכן נמצאים פרטי הקשר | להשאלות שלי |
| 2 | בקשה נדחתה | השואל | הפריט והתאריכים; הצעה לחפש חלופה | לקטלוג |
| 3 | אדמין אישר משתמש | המשתמש | "ברוך הבא לקהילה" | כניסה לאתר |
| 4 | אדמין אישר פריט | בעל הפריט | הפריט פורסם בקטלוג | לצפייה בפריט |
| 5 | יום לפני מועד ההחזרה | השואל | תזכורת להחזיר מחר | להשאלות שלי |
| 6 | השאלה עברה לאיחור | השואל **וגם** בעל הפריט | מועד ההחזרה עבר | להשאלות שלי / לפריטים שלי |
| 7 | השואל סימן "החזרתי" | בעל הפריט | בקשה לאשר את ההחזרה | לאישור ההחזרה |

כל המיילים בעברית, מימין לשמאל, בצבעי האתר, עם כפתור אחד שמוביל לעמוד הרלוונטי.

### איך זה בנוי

| קובץ | תפקיד |
|---|---|
| `lib/email/template.ts` | תבנית HTML אחת לכל המיילים, וגרסת טקסט פשוט |
| `lib/email/send.ts` | פונקציית השליחה המרכזית: קוראת ל-Resend ורושמת את התוצאה ב-`email_log` |
| `lib/email/notify.ts` | פונקציה לכל אירוע, שמרכיבה את התוכן ואת הנמען |
| `lib/actions/*.ts` | ה-Server Actions קוראות לפונקציית ההודעה **אחרי** שהפעולה עצמה הצליחה |
| `app/api/cron/daily/route.ts` | המשימה היומית (אירועים 5 ו-6) |

### אבטחת המפתחות

- `RESEND_API_KEY` נקרא רק ב-`lib/email/send.ts`, קובץ שמסומן `server-only`: ניסיון לייבא אותו לקומפוננטת
  לקוח מכשיל את ה-build. למפתח אין קידומת `NEXT_PUBLIC_`, ולכן הוא לא נכלל בקוד שנשלח לדפדפן.
- המפתח מוגדר כמשתנה סביבה ב-Vercel ואינו מופיע בקוד, ב-git או ב-`.env.example`.
- הדפדפן לעולם לא פונה ל-Resend. הוא מפעיל Server Action, והשרת הוא ששולח.
- כדי לפנות לנמען, השרת צריך את כתובת המייל של משתמש *אחר* – מידע שהמשתמש המבצע אינו רשאי לקרוא.
  הקריאה נעשית בצד השרת בלבד, אחרי שהפעולה אושרה, והכתובת אינה חוזרת לדפדפן.
- שמות משתמשים ושמות פריטים שנכנסים לתוכן המייל עוברים escaping, כדי שלא יהיה אפשר להזריק HTML לתיבת
  הדואר של מישהו אחר דרך שם של פריט.

### התנהגות בכשל

- שליחת מייל לעולם לא מכשילה את הפעולה: אם Resend לא זמין, הבקשה עדיין נשמרת והמשתמש מקבל אישור.
  הכישלון נרשם ב-`email_log` עם `status = failed`.
- אם `RESEND_API_KEY` לא מוגדר, המיילים מדולגים ונרשמים כ-`skipped`, והאתר ממשיך לעבוד כרגיל.
- משתמש חסום אינו מקבל מיילים.

### יומן המיילים

כל ניסיון שליחה נרשם ב-`email_log` (סוג, נמען, הישות הקשורה, סטטוס וזמן). היומן משמש לשני דברים:

1. **מניעת כפילויות** – תזכורת או הודעת איחור נשלחות פעם אחת לכל השאלה ונמען, גם אם המשימה רצה שוב.
2. **שקיפות** – 20 הרשומות האחרונות מוצגות לאדמין בפאנל הניהול, תחת "יומן מיילים".

היומן אינו שומר את תוכן ההודעה או את כתובת הנמען.

## המשימה היומית – Vercel Cron

`vercel.json` מגדיר קריאה יומית בשעה 05:00 UTC (בבוקר לפי שעון ישראל) לנתיב `/api/cron/daily`. המשימה:

1. מסמנת כ-`late` כל השאלה פעילה שמועד ההחזרה שלה עבר (והמסד יוצר התראת איחור באתר לשני הצדדים).
2. שולחת תזכורת לכל שואל שמועד ההחזרה שלו מחר, גם במייל וגם כהתראה באתר.
3. שולחת הודעת איחור לשואל ולבעל הפריט בכל השאלה שבאיחור.

**הגנה:** הנתיב נגיש מהאינטרנט, ולכן הוא דורש את הכותרת `Authorization: Bearer <CRON_SECRET>`. Vercel
מצרף אותה אוטומטית לקריאות ה-Cron. ההשוואה נעשית בזמן קבוע (`timingSafeEqual`), ובלי הסוד מוחזר 401.
פונקציית המסד שהמשימה מפעילה ניתנת להרצה רק עם ה-service role.

בדיקה ידנית:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://<האתר>/api/cron/daily
# {"ok":true,"newlyLate":1,"reminders":2,"overdueNotices":2}
```

## Supabase Realtime – עדכונים בזמן אמת

### למה זה מוסיף ערך

תיאום איסוף של פריט הוא שיחה: "מתי נוח לך?", "אני למטה". אם צריך לרענן את הדף כדי לראות תשובה, אנשים
חוזרים לוואטסאפ. עם Realtime הודעה חדשה מופיעה מיד, מונה ההתראות מתעדכן, וסטטוס ההשאלה משתנה אצל הצד
השני ברגע שהבעלים מאשר.

### איך זה בנוי

| קובץ | תפקיד |
|---|---|
| `components/RealtimeRefresher.tsx` | מאזין לשינויים בהודעות, בהתראות, בבקשות ובהשאלות, ומבקש מהשרת לרנדר מחדש את הדף |
| `lib/supabase/realtime.ts` | מוסר לדפדפן את הטוקן קצר-המועד של המשתמש המחובר |
| `lib/actions/realtime.ts` | מחדש את הטוקן לפני שהוא פג, כדי שלשונית פתוחה תמשיך לקבל עדכונים |
| `supabase/migrations/006_…sql` | מוסיף את ארבע הטבלאות לשידור |

### אבטחה

- הדפדפן **רק מאזין**. האירוע הוא אות בלבד; הנתונים שמוצגים נשלפים בשרת, כמו בטעינת דף רגילה. כל כתיבה
  ממשיכה לעבור דרך Server Action ופונקציית מסד.
- Realtime מחיל את מדיניות ה-RLS: משתמש מקבל אירוע רק על שורה שהוא רשאי לקרוא. הודעה בצ'אט מגיעה רק
  לשני המשתתפים בו.
- ה-CSP מתיר חיבור רק לאתר עצמו ולכתובת ה-Supabase של הפרויקט.
- במצב דמו (בלי Supabase) הרכיב מרענן את הדף כל כמה שניות במקום להאזין.
