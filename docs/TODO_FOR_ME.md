# מה נשאר לי לעשות ידנית

עודכן: 13.10.2026. הצעדים מסודרים לפי חשיבות לציון.

## כבר בוצע (אין צורך לגעת)

- כל חמשת ה-migrations הוחלו על מסד הנתונים בפרודקשן.
- `CRON_SECRET` הוגדר ב-Vercel (ערך אקראי; אין צורך לדעת אותו, Vercel שולח אותו לבד).
- משתני Supabase מוגדרים ב-Vercel, ומצב הדמו כבוי.
- הגרסה האחרונה של הענף `final-polish` פרוסה ב-https://community-share-bice.vercel.app.
- נבדק שאין מפתחות או קובצי `.env` בהיסטוריית ה-git – אין מה לסובב.

## 1. לחבר את Resend (15 נקודות במחוון – בלי זה המיילים לא נשלחים)

1. להירשם ב-https://resend.com **עם אותה כתובת שבה נרשמת לאתר** (ראו ההערה למטה).
2. בתפריט: API Keys ← Create API Key ← הרשאת "Sending access". להעתיק את המפתח (מתחיל ב-`re_`).
3. ב-Vercel: הפרויקט ← Settings ← Environment Variables ← להוסיף ל-Production:
   - `RESEND_API_KEY` = המפתח (לסמן Sensitive)
   - `EMAIL_FROM` = `שיתוף קהילתי <onboarding@resend.dev>`
4. Deployments ← שלוש הנקודות ליד הפריסה האחרונה ← Redeploy.
5. לבדוק: לאשר פריט או בקשה באתר, ולראות שהמייל הגיע ושב"יומן מיילים" בפאנל הניהול הסטטוס הוא "נשלח".

**הגבלה חשובה:** בלי דומיין מאומת, Resend שולח רק לכתובת של בעל החשבון ב-Resend. מיילים לכתובות אחרות
ייכשלו ויופיעו ביומן כ"נכשל". שתי דרכים להתמודד:

- **להדגמה (פשוט):** להשתמש בחשבון שלך כצד שמקבל את המייל. למשל: משתמש הדמו שולח בקשה על פריט *שלך*,
  והמייל על הבקשה מגיע אליך.
- **מלא:** לאמת דומיין ב-Resend (Domains ← Add Domain, ולהוסיף את רשומות ה-DNS), ואז לשנות את
  `EMAIL_FROM` לכתובת מהדומיין. אחרי זה המיילים מגיעים לכל אחד.

## 2. ליצור משתמשי דמו ונתוני דמו

1. לבחור שתי סיסמאות (לפחות 10 תווים, עם אות וספרה).
2. ליצור קובץ `.env.local` זמני עם הערכים האמיתיים של `NEXT_PUBLIC_SUPABASE_URL` ו-`SUPABASE_SERVICE_ROLE_KEY`
   (מ-Vercel ← Settings ← Environment Variables), ועם `DEMO_USER_PASSWORD` ו-`DEMO_ADMIN_PASSWORD`.
3. להריץ:
   ```bash
   node --env-file=.env.local --experimental-strip-types scripts/create-demo-users.ts
   ```
4. ב-Supabase ← SQL Editor: להדביק את התוכן של `supabase/seed.sql` וללחוץ Run.
5. להחזיר ב-`.env.local` את `USE_MOCK_DATA=true` ולמחוק ממנו את המפתח הסודי.

אפשר גם לבקש ממני לעשות את צעדים 2–5: צריך רק לומר לי אילו סיסמאות לקבוע.

הסקריפט יוצר את `demo.user@example.com` ואת `demo.admin@example.com`. אלה כתובות שאינן קיימות, ולכן
משתמשי הדמו לא יקבלו מיילים בפועל.

## 3. לעבור על תוכנית הבדיקות בדפדפן

`docs/TEST_PLAN.md` – במיוחד פרק 1 (המסלול המרכזי) ופרק 6 (טלפון, רוחב 375px). הקוד נבדק אוטומטית מול
מסד הנתונים, אבל אף אחד עוד לא עבר על המסכים בעיניים ולחץ על הכפתורים בדפדפן אמיתי, מלבד ההרשמה שלך.
אם משהו נראה שבור או לא עובד – לשלוח לי צילום מסך.

## 4. להשלים את ה-README

- להוסיף צילומי מסך (יש טבלה ריקה שמחכה להם).
- למלא את הסיסמאות של משתמשי הדמו – או, עדיף, למסור אותן לבודק בנפרד ולא לשים אותן ב-GitHub ציבורי.

## 5. לדחוף את הענף ל-GitHub

```bash
git push -u origin final-polish
```

ואז לפתוח Pull Request ל-`main` ולמזג. עד אז GitHub מציג את הגרסה הישנה.

רשות: לחבר את המאגר ל-Vercel (Settings ← Git ← Connect), כדי שכל push יעלה לבד.

## 6. לעדכן את מסמך האפיון

להדביק מ-`docs/SPEC_ADDITIONS.md` את הסעיפים: משפט הבעיה, חיבורים חיצוניים, מבנה הנתונים, הרשאות
ותרשימי הזרימה.

## 7. להחליט על שלב ה-AI (רשות)

כפתור "✨ נסח לי תיאור" בטופס הוספת פריט, שקורא ל-Claude API. לא בוצע, כי הפרומפט דרש לשאול קודם.
דורש מפתח `ANTHROPIC_API_KEY` וכרוך בעלות קטנה לכל שימוש. אם רוצים – לומר לי, ואבנה אותו.

## 8. לוודא ב-Supabase (פעם אחת)

- Authentication ← URL Configuration: Site URL הוא `https://community-share-bice.vercel.app`, וברשימת
  ה-Redirect URLs מופיע `https://community-share-bice.vercel.app/auth/callback`.
- Authentication ← Sign In / Providers ← Email: האפשרות "Confirm email" מופעלת.

## 9. אחרי ההצגה

לחסום או למחוק את שני משתמשי הדמו בפאנל הניהול – יש להם סיסמאות שאנשים אחרים מכירים, ואחד מהם אדמין.
